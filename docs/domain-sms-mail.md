# Домен, SMS и почта: что сделать по шагам

Все три настройки делаются в одном файле `.env` на сервере и применяются одной командой. Ключи и пароли пишите **только в `.env`**, никому их не присылайте (ни в чат, ни в переписку).

## 0. Как править `.env` на сервере (общее для всех частей)

1. Зайдите на сервер по SSH (как вы это делаете для `git pull`).
2. Перейдите в папку сайта: там, где лежит файл `docker-compose.yml`. Проверка: команда `ls` должна показать `docker-compose.yml` и `.env`.
3. Откройте файл:

```bash
nano .env
```

4. Стрелками найдите нужную строку (поиск - `Ctrl+W`, набрать слово, `Enter`). Строка, которая начинается с `#`, выключена: чтобы включить, удалите `#` в начале.
5. Вставка скопированного: правая кнопка мыши в окне терминала или `Shift+Insert` (зависит от программы; в Windows Terminal и PuTTY обычно правая кнопка).
6. Сохранить: `Ctrl+O`, затем `Enter`. Выйти: `Ctrl+X`.
7. Применить изменения (обычный `restart` **не** перечитывает `.env`, нужна именно эта команда):

```bash
sudo docker compose up -d --build
```

8. Если что-то не работает, посмотрите журнал сайта (последние 60 строк):

```bash
sudo docker compose logs shop --tail 60
```

## 1. Домен

Что должно получиться: сайт открывается по `https://ваш-домен.ru` с замочком. Сертификат (HTTPS) сайт получает **сам** (Caddy, Let's Encrypt), покупать его не нужно.

### 1.1. Узнайте адрес сервера

В консоли Yandex Cloud: «Compute Cloud» → «Виртуальные машины» → ваша машина → строка «Публичный IPv4-адрес» (четыре числа через точки, например `51.250.10.20`). Запишите его.

Важно: адрес должен быть **постоянным**. Если он динамический, после остановки и запуска машины он поменяется, и сайт «пропадёт». В Yandex Cloud это делается в «Virtual Private Cloud» → «IP-адреса» (у адреса машины включить «статический»/«зарезервировать»). Названия пунктов в консоли могут немного отличаться.

### 1.2. Откройте порты 80 и 443

Там же, в Yandex Cloud: «Virtual Private Cloud» → «Группы безопасности» → группа вашей машины → правила **входящего** трафика. Нужны два правила: протокол TCP, порт 80, источник `0.0.0.0/0` и то же для порта 443. Порт 80 нужен именно для получения сертификата. Если группы безопасности у машины нет, ничего делать не надо.

### 1.3. Привяжите домен к серверу в Reg.ru

1. Личный кабинет Reg.ru → «Домены» → ваш домен → «DNS-серверы и управление зоной».
2. Убедитесь, что у домена указаны серверы `ns1.reg.ru` и `ns2.reg.ru`. Если там другие, записи правятся там, где эти серверы указаны, а не в Reg.ru.
3. Удалите старые записи типа **A** и **AAAA** для этого домена (Reg.ru часто сам ставит адрес своей «заглушки»). Записи **MX** и **TXT** (почта) не трогайте.
4. Добавьте запись: тип **A**, имя `@` (это сам домен), значение - IP из шага 1.1.
5. Подождите. Обычно 10-60 минут, иногда до суток. Проверка с сервера (должна вывести ваш IP):

```bash
getent hosts ваш-домен.ru
```

Если выводится чужой адрес или пусто, значит, запись ещё не обновилась или старая запись осталась.

Если нужен ещё и `www.ваш-домен.ru`, скажите: для него нужна отдельная настройка (иначе у `www` будет ошибка сертификата), без неё `www` лучше не создавать.

### 1.4. Впишите домен в `.env`

Две строки (замените на свой домен; в первой **без** `https://`, во второй **с** ним):

```
SITE_ADDRESS=ваш-домен.ru
PUBLIC_URL=https://ваш-домен.ru
```

Затем примените (раздел 0, шаг 7). Сертификат выдаётся за минуту-две после того, как домен «дошёл» до сервера. Если сайт по https не открывается, посмотрите журнал Caddy:

```bash
sudo docker compose logs caddy --tail 60
```

Там будет видно, чего не хватает (чаще всего: домен ещё не указывает на сервер или закрыт порт 80).

## 2. SMS-коды для входа (SMS.ru)

Что должно получиться: на странице входа появляется способ «Код по SMS», покупателю на телефон приходит код.

1. Зарегистрируйтесь на sms.ru, подтвердите номер и пополните баланс на небольшую сумму (одно SMS стоит несколько рублей, актуальные цены в кабинете).
2. Возьмите ключ `api_id`: в личном кабинете sms.ru раздел для разработчиков/API («Программистам», «Авторизация по api_id»). Это длинная строка из букв, цифр и дефисов. Это секрет, как пароль.
3. Если в кабинете включено ограничение по IP, добавьте туда IP сервера (или отключите ограничение), иначе SMS не уйдут.
4. Имя отправителя (`SMS_SENDER`) **на первое время не заполняйте**: SMS уйдут от стандартного отправителя. Своё имя вроде SOLEHOUSE нужно отдельно регистрировать и согласовывать в sms.ru (это занимает время и бывает платным); когда его одобрят, впишите его в `SMS_SENDER` точно так же, как оно одобрено.
5. Впишите в `.env` (значение `SMS_PROVIDER` именно `smsru`; вариант `console` на боевом сервере запрещён):

```
SMS_PROVIDER=smsru
SMS_API_KEY=ваш_api_id_из_кабинета
SMS_DAILY_CAP=300
```

`SMS_DAILY_CAP` - предохранитель: не больше стольких SMS в сутки, чтобы никто не мог «слить» ваш баланс перебором номеров.

6. Примените (раздел 0, шаг 7) и проверьте: откройте `https://ваш-домен.ru/login`, выберите «Код по SMS», введите свой номер. Код должен прийти за несколько секунд. Не пришёл: журнал сайта (раздел 0, шаг 8) и баланс в sms.ru.

## 3. Почта для писем (сброс пароля, подтверждение почты)

Что должно получиться: покупатель может подтвердить почту и сбросить пароль по ссылке из письма. Пока почта не настроена, эти кнопки на сайте скрыты, остальное работает.

### 3.1. Почтовый ящик на вашем домене в Reg.ru

1. В кабинете Reg.ru откройте услугу «Почта» для вашего домена и создайте ящик, например `shop@ваш-домен.ru`. Задайте пароль и запишите его.
2. В `.env` впишите (замените домен и пароль; `SMTP_FROM` должен быть **тем же адресом**, что и `SMTP_USER`, иначе сервер почты письма отклонит):

```
SMTP_HOST=mail.hosting.reg.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=shop@ваш-домен.ru
SMTP_PASS=пароль_от_ящика
SMTP_FROM=SOLEHOUSE <shop@ваш-домен.ru>
```

По справке Reg.ru: сервер `mail.hosting.reg.ru`, порт 465 с шифрованием, логин - полный адрес ящика. Если с этим портом не работает, попробуйте `SMTP_PORT=587` и `SMTP_SECURE=false`.

3. Записи `MX` и `TXT` в DNS-зоне Reg.ru не удаляйте: они нужны, чтобы письма доходили и не попадали в спам.

### 3.2. Запасной вариант: ящик на Яндексе

Если ящик Reg.ru не заработал, подойдёт ящик на Яндекс Почте (в настройках ящика включите доступ по протоколу IMAP/SMTP и создайте «пароль приложения»):

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=ваш_адрес@yandex.ru
SMTP_PASS=пароль_приложения
SMTP_FROM=SOLEHOUSE <ваш_адрес@yandex.ru>
```

### 3.3. Проверка

1. Примените (раздел 0, шаг 7).
2. Войдите на сайт (по SMS или через Telegram), откройте кабинет → профиль, впишите свою почту и сохраните.
3. Должно прийти письмо со ссылкой «подтвердить почту». Затем проверьте «Забыли пароль?» на странице входа.
4. Письмо не пришло: посмотрите папку «Спам» и журнал сайта (раздел 0, шаг 8): в нём будет причина (неверный пароль, закрытый порт и т. п.; сам пароль в журнал не попадает).

## Итоговый кусок `.env`

```
SITE_ADDRESS=ваш-домен.ru
PUBLIC_URL=https://ваш-домен.ru

SMS_PROVIDER=smsru
SMS_API_KEY=ваш_api_id_из_кабинета
SMS_DAILY_CAP=300

SMTP_HOST=mail.hosting.reg.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=shop@ваш-домен.ru
SMTP_PASS=пароль_от_ящика
SMTP_FROM=SOLEHOUSE <shop@ваш-домен.ru>
```

После правок: `sudo docker compose up -d --build`.
